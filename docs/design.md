# 原理、范围与证据

```text
目录 / 资产清单 → 受限读取 → 识别版本与静态线索
    → 匹配有来源和日期的规则 → 保留未知项与缺口
    → 门禁判断 → 文本 / JSON / 离线 HTML
```

## 结构

| 路径 | 职责 |
|---|---|
| riskcheck.py | 文件读取、规则匹配、证据汇总、门禁、报告和 CLI |
| riskcheck_data/rules.json | 唯一内置规则来源，不含可执行代码 |
| schemas/inventory.schema.json | 编辑器提示；运行时仍使用自身字段校验 |
| tests/ | 边界、输入安全与可下载制品测试 |
| tools/build_release.py | 便携/源码 ZIP 和摘要清单构建 |

保留小型单模块，避免为了形式拆出过多接口。pyproject 明确声明模块和数据包；wheel 与便携版共享同一规则数据；`__version__` 是工具版本的唯一来源。

## 证据层次

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| .nvmrc、Dockerfile 标签 | 项目声明的版本 | 运行中的服务一定使用它 |
| runtime 清单 | 部署系统/操作者声明的版本 | 工具已连接主机核实 |
| affected | 版本命中本条规则 | 攻击可达或已经入侵 |
| static_hint | 存在相关配置特征 | 作用域、模块编译、生效关系与可利用性 |
| artifact_match | 完整摘要命中已知制品 | 制品已执行 |
| exposure | 清单记录历史安装/执行 | 已完成取证和影响面确认 |
| vendor_attested | 用户提交逐条厂商修复依据 | 工具独立核实了公告或二进制 |

`context=false` 不抹去版本命中，当前升级不覆盖历史暴露。版本范围、未知分支、预发布、厂商后缀和 Go 最低语言版本要求在证据不足时保持 unknown。Rust 兼容包装层不能因为同锁文件出现安全父包就被放行。

nginx 检查不验证 include 展开和作用域，故产生缺口；TOML 锁文件只读取支持的单行字段。公告严重度和本项目 CI 优先级独立保存，不累加成虚构的风险总分。

## 读取和报告边界

不执行目标程序、运行包管理器或连接网络。不跟随符号链接，限制单文件大小、文件/目录数量和深度。跳过目录清单写入报告；解析错误不回显配置原文或异常中的敏感内容。

HTML 转义输入，使用禁止脚本的 CSP，无外部资源。文本清理终端控制字符。JSON 仍包含资产名称、版本和相对路径，应按内部资料保管。这不是抗主动篡改的取证隔离；不可信主机应导出只读副本至干净系统。

## 门禁与覆盖

缺口或 unknown 返回 2；无缺口且达到阈值的风险返回 1；其余返回范围内通过 0。空扫描不通过，阈值以下风险仍保留。

通过仅覆盖给定资产、可识别文件和这批规则，不涵盖未知 CVE、运行态发现、真实 TLS 阻断或完整取证。Node/Go/Rust 的 CA 相关版本更新不能代替检查系统和自定义证书信任库。
